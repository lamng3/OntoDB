One query, page by page, through a database built for ontologies

OntoDB stores RDF as 64-bit ids in B+ trees and answers SPARQL with a cost-based optimizer, a buffer pool and a write-ahead log. Everything below was printed by the real shell: its plans, its trees, every page the buffer pool fetched while it answered one LUBM query, and what it did after an abrupt exit.

A database directory survives an abrupt exit

ontodb mydb runs each statement as a transaction and forces its log records to mydb/wal before the prompt returns. \checkpoint writes a snapshot and resets the log. Here the shell exits with \crash, which flushes nothing, and the last 10 bytes of the log are cut off by hand to stand in for a write the disk never finished.

Everything under a class is a range scan

On a slice of the Gene Ontology, \hindex build numbers the class hierarchy so that each class owns a few integer intervals, kept in a B+ tree. "Every class at or below C" becomes one range scan per interval. The same intervals can restrict a vector search to the classes under C.
